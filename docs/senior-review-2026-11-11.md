Подтверждено **15 замечаний**; **16 автоматических регрессионных тестов** воспроизводят 14 из них. Потеря черновика CO₂ при обновлении дополнительно подтверждена выполнением фактических JS-функций в Node с минимальной DOM-моделью; реальный браузерный сценарий остаётся обязательной приёмочной проверкой.

P1 — исправить первым из-за потери данных или недостоверных входов/решений. P2 — обязательное исправление следующими небольшими шагами. Это ревью корректности и архитектуры; оно не заменяет полевую валидацию физических моделей или полный аудит безопасности.

## Подтверждённые замечания

### R01 · P1 · Сбой повторной обработки удаляет ранее подтверждённые данные

Место: [pipeline.py:262](../app/core/documents/pipeline.py#L262), извлечение вызывается позднее на строке 288. Старые данные удаляются до завершения извлечения и валидации. При временной ошибке LLM акт возвращается в очередь, а его запись истории уже удалена; прежний рассчитанный рейтинг остаётся в БД.

Воспроизведение: загрузить акт разбора DEMO-002 → имитировать `ExtractionUnavailable` → reprocess. Подтверждено: до запроса есть событие DOC_BASE, после него список пустой.

Минимальное исправление: сначала получить и проверить новый результат; затем атомарно заменить вклад документа. Пересчитывать объединение старых и новых скважин. Убрать предварительные удаления, дублируемые между pipeline/load.

Тест: `test_review_failed_reprocessing_keeps_accepted_document_data`.

### R02 · P1 · Удаление документа удаляет независимый прямой импорт

Места: [source_connectors.py:60](../app/core/source_connectors.py#L60), [pipeline.py:84](../app/core/documents/pipeline.py#L84), [db/documents.py:117](../app/db/documents.py#L117). Прямой Excel-импорт и документ получают одинаковый batch ID. Документ записывает его как свой; удаление документа удаляет и исходный независимый импорт. Восстановление соседних документов не восстанавливает ручной импорт.

Воспроизведение: напрямую импортировать ДАРС → загрузить тот же файл как документ → удалить документ. Исходная телеметрия DEMO-002 меняется/исчезает; это подтверждено интеграционным тестом.

Исправление: явно хранить владельца/происхождение загрузки и удалять только принадлежащий документу вклад. Сохранить идемпотентность и совместимость уже загруженных данных; не маскировать проблему повторным импортом всех соседей.

Тест: `test_review_deleting_document_preserves_independent_manual_import`.

### R03 · P1 · Проверка цитаты допускает неверную размерность и обратный булев результат

Место: [extract.py:185](../app/core/documents/extract.py#L185), булевы значения проходят через строку 199. Масштабирование ×100/÷100 разрешено для любого числового поля. `215 мг/л` принимается как подтверждённое цитатой «Хлориды: 21500 мг/л». `True` принимается по цитате «Коррозия не обнаружена».

Исправление: разрешённые преобразования привязать к конкретному полю/единице; сохранить правильный случай `85% → 0.85` для эффективности ингибитора. Для булевых фактов проверять подтверждение/отрицание, неоднозначный текст оставлять неподтверждённым.

Тесты: `test_review_numeric_quote_does_not_allow_factor_100_for_chlorides`, `test_review_boolean_quote_does_not_reverse_corrosion_negation`.

### R04 · P1 · Неизвестное отклонение закачки ошибочно подтверждает защиту

Место: [rating_builder.py:628](../app/core/rating_builder.py#L628). Условие допускает `deviation is None` как подтверждение, хотя описание требует известного отклонения ниже порога.

Восемь замеров с ингибитором 0.9, скоростью 0.05, без отклонения и защитного исполнения дают `protection=effective`, `model_ntc_raw=0.5714`, `model_ntc=0.2857`. Список пробелов одновременно сообщает об отсутствии отклонения.

Исправление: разделить «меры заявлены» и «эффективность подтверждена»; неизвестное обязательное значение не даёт скидку риска. Предлагаемая семантика — `unconfirmed` до подтверждения, а не `insufficient` без доказанного нарушения.

Тест: `test_review_missing_injection_deviation_cannot_confirm_protection`.

### R05 · P2 · Смешение источников продлевает срок жизни чужих показателей

Места: [db/sources.py:104](../app/db/sources.py#L104), [normalization.py:35](../app/core/normalization.py#L35). После слияния остаётся только `DARS+KHIMIK`; лабораторное окно применяется ко всей строке.

Подтверждено через SQL Server: обводнённость ДАРС 95% остаётся текущей через 10 дней при лимите 7 дней, потому что в тот же момент была проба хлоридов ХИМИК с окном 30 дней.

Исправление: сохранить источник/время каждого поля либо нормализовать реальные наблюдения до их объединения в текущий срез. Не менять общий публичный контракт телеметрии без проверки потребителей.

Тест: `test_review_mixed_source_does_not_extend_dars_field_as_lab_sample`.

### R06 · P2 · Тренд строится по перенесённым значениям как по новым замерам

Место: [features.py:27](../app/core/features.py#L27). Значения из `imputed_fields` попадают в регрессию и учитываются при минимуме наблюдений.

Два настоящих замера обводнённости 40 и 60 плюс шесть строк других показателей дают тренд 1.6667/сут и срабатывание правила роста при минимуме 8 замеров.

Исправление: брать реальные наблюдения конкретного поля, считать их уникальные времена. Перенос значений оставить для текущего состояния, исключить из доказательств тренда.

Тест: `test_review_trend_requires_actual_measurements_not_forward_fills`.

### R07 · P2 · Семидневное правило зависит от постороннего показателя и часа отбора

Место: [rules.py:86](../app/core/rules.py#L86). Последняя строка даты может содержать перенесённую обводнённость и немедленно отклоняет день с настоящим более ранним замером. Отсечение 6×24 часа также теряет первую из семи дат при часовом сдвиге последней пробы.

Исправление: выбрать настоящие замеры нужного поля по согласованным календарным датам, затем проверять семь последовательных дат. Явно закрепить используемый часовой пояс.

Тест: `test_review_persistence_uses_measurement_even_if_other_source_is_later`. Перед исправлением дополнить отдельным тестом часового сдвига и границ дат.

### R08 · P2 · Reprocess освобождает уже захваченный другим worker документ

Место: [pipeline.py:367](../app/core/documents/pipeline.py#L367). Безусловный переход `processing → queued` позволяет второму worker захватить тот же документ, пока первый работает.

Воспроизведение без зависимости от тайминга: claim → reprocess → второй claim возвращает документ вместо `None`.

Исправление: атомарный переход с условием текущего состояния/владельца. Повтор активного задания должен возвращать занятость либо текущее задание, не снимать claim. Отдельно проверить восстановление действительно устаревших заданий.

Тест: `test_review_reprocessing_must_not_release_an_active_claim`.

### R09 · P2 · Проверка ИИ-предложения контролирует ID бригады, но не доступность

Место: [proposal_agent.py:224](../app/core/proposal_agent.py#L224). Известная бригада проходит проверку при `busy`, с датой вне окна доступности и позже срока рейтинга. Ограничение в system prompt не заменяет серверную проверку.

Исправление: проверять статус, дату, окно, крайний срок и требуемые ограничения. При неподтверждённой доступности возвращать `crew=null` с причиной. Согласовать поведение расписания без дат отдельно от явно нарушенного окна.

Тесты: `test_review_reject_busy_crew_even_when_id_is_known`, `test_review_reject_crew_date_outside_window_and_rating_deadline`.

### R10 · P2 · Пустой push расписания не очищает прежние бригады

Место: [ingestion.py:130](../app/api/routes/ingestion.py#L130). Корректный пустой список отклоняется с 422, оставляя старую доступность. Pull-путь пустой список принимает.

Исправление: различать корректное пустое расписание и непустой список, все строки которого ошибочны. Для первого сохранять очистку с источником/датой.

Тест: `test_review_empty_schedule_can_clear_previously_available_crews`.

### R11 · P2 · Дедупликация пропусков стирает новые недостающие показатели

Место: [proposal_language.py:76](../app/core/proposal_language.py#L76). Отношение включения наборов слов трактуется как дубликат: «нет CO₂» подавляет «нет CO₂ и хлоридов», теряя сведения о хлоридах.

Исправление: точная нормализованная дедупликация либо структурированные ключи показателей. Предпочтительно упростить текущую нечёткую эвристику, сохранив дополнительные сведения.

Тест: `test_review_gap_deduplication_keeps_additional_missing_indicator`.

### R12 · P2 · Windows stop/restart может принять чужой Python за этот сервис

Место: [service.py:73](../standalone/cli/service.py#L73). Проверка живого PID принимает любой путь, заканчивающийся `python.exe`/`pythonw.exe`. При повторном использовании PID stop может завершить чужой процесс.

Тест WinAPI-границы на Linux возвращает `C:\unrelated\python.exe`: `_alive()` ошибочно возвращает True. Реальные процессы при воспроизведении не завершались.

Исправление: проверять идентичность экземпляра приложения и время создания процесса, как минимум ожидаемый runtime и команду запуска. Сохранять подтверждённую идентичность вместе с PID; при сомнении не завершать процесс. Проверить реальные start/status/stop/restart на Windows.

Тест: `test_review_windows_pid_must_belong_to_this_application`.

### R13 · P2 · Сборщик продолжает работу после SyntaxError

Место: [build_windows.py:206](../standalone/build/build_windows.py#L206). Результат `compileall.compile_dir` игнорируется. Настоящий файл `app/broken.py` с синтаксической ошибкой печатает ошибку, но helper завершается нормально. Ошибка в standalone CLI может не попасть в текущий smoke, импортирующий API.

Исправление: ошибка компиляции, недостающая DLL или неверный манифест должны завершать единую сборочную команду до публикации ZIP. Добавить проверку импорта standalone CLI в Windows smoke.

Тест: `test_review_build_fails_if_python_source_cannot_compile`.

### R14 · P2 · Обновление карточки теряет введённые значения формы CO₂

Место: [index.html:1590](../dashboard/index.html#L1590), пересоздание карточки на строке 924. Форма не сохраняет черновик и не участвует в `cardDirty`; обновление каждые 60 секунд создаёт пустую форму. Ввод может потеряться также при обновлении других блоков.

Выполнение фактических JS-функций в Node подтвердило: введённая температура `60` после повторного render становится пустой. Исправление: отдельное состояние черновика и запроса по скважине; обновлять результат без пересоздания активной формы.

Нужна браузерная проверка: ввод → автоматическое обновление → значения остаются → расчёт → корректный результат/история; дополнительно смена скважины и ответ устаревшего запроса.

### R15 · P2 · Некорректное время baseline принимается моделью вероятности

Место: [math_model.py:74](../app/core/math_model.py#L74). Строка `NaN` преобразуется в float, но время проверяется только на `<0`. Артефакт с `time_days='NaN'`, `survival=0.5` выдаёт выглядящую допустимой вероятность 0.5.

Исправление: конечные, уникальные и строго возрастающие времена; конечные survival/коэффициенты; неверный артефакт возвращает `Unavailable`, а не прогноз. Дополнить тестами дубликатов времён и границ горизонта.

Тест: `test_review_math_model_rejects_nonfinite_baseline_time`.

## Архитектура и минимизация кода

1. Сохранить Python/FastAPI/SQL Server и браузерный JS. Здесь достаточно модульного монолита и явных функций; новые универсальные фреймворки/слои репозиториев не обоснованы.
2. Выделить общий отбор реальных наблюдений конкретного поля с его временем и источником. Использовать в нормализации, трендах, устойчивости и пробелах. Это устраняет расхождения правил времени, а не просто переносит функции.
3. Собрать сведения об источниках в небольшой публичный каталог; убрать зависимость агента от приватного `rating_builder._Sources` и дубли классификации источников.
4. Один путь применения вклада документа в транзакции; явное владение загрузкой. После этого пересмотреть `_restore_shared()` и повторные удаления как компенсирующий код.
5. Сократить ранжирование после сортировки с O(n²) до одного прохода, сохранив Excel-места при равных индексах: [rating.py:231](../app/core/rating.py#L231).
6. Пакетировать чтение ID и запись CO₂; не читать все скважины ради одной и не выполнять SELECT+INSERT на каждую строку. Убрать блокирующие parsing/SQL из event loop async CO₂-import; добавить проверку отзывчивости API во время импорта.
7. У формы должен быть один владелец состояния, выбранной скважины и незавершённого запроса. Разделять JS по ответственности только там, где это позволяет удалить дублирование и сохранить черновик; сборщик frontend пока не требуется.
8. Одна проверенная команда сборки. `release_co2_demo.sh` с фиксированными веткой, commit message и списком 30 файлов — разовый инструмент восстановления; не превращать его в постоянную архитектуру релизов.

Цель — меньшая сложность и объём сопровождения при тех же возможностях. На каждом шаге фиксировать размер production-кода и число удалённых дублирующих путей. Удаление проверки данных ради сокращения строк не является улучшением.

Порядок работ и точка подтверждения: [upgrade-plan-2026-11-11.md](upgrade-plan-2026-11-11.md).
