# План исправлений по QA-аудиту

Дата: 12.11.2026. Статус: **этапы 0–4 одобрены пользователем; исправления и приёмка готовы, выполняется поставка**. Основание: [qa-review-2026-11-12.md](qa-review-2026-11-12.md), проверяемая поставка `61c902a`.

Цель: понятный первый запуск, сохранность действий оператора, честные статусы и простой путь подключения четырёх источников. Численные модели, пороги мероприятий и единицы расчёта не меняются. Существующий полный рейтинг и Excel остаются доступны. Новая frontend-сборка, универсальные классы коннекторов и отдельные сервисы не требуются.

## Этап 0. Сначала воспроизведение и сохранность

Замечания Q01–Q03.

До исправлений закрепить регрессиями:

- loaded → ошибка reprocess → очистка failed: прежний вклад сохраняется при обычной очистке ошибок;
- явное полное/одиночное удаление по-прежнему удаляет выбранный вклад и пересчитывает затронутые скважины;
- крестик, клик снаружи, Esc, повторный клик той же строки, переход к другой скважине и ошибка сохранения не теряют ввод без решения оператора;
- поздний успех и поздняя ошибка A не меняют уже открытую B.

Реализация:

1. Различать состояние последней обработки и наличие принятой версии. У failed/not_recognized с сохранённым вкладом показывать это явно.
2. Обычная очистка ошибок на сервере пропускает документы с принятым вкладом, даже если интерфейс устарел; ответ сообщает число пропущенных. В меню считать именно безопасно удаляемые документы. У полного удаления подтверждение учитывает весь сохранённый вклад, включая failed.
3. Ввести одну проверку несохранённых изменений для всех путей закрытия/переключения. Повторное открытие уже открытой скважины сохраняет форму. При отмене закрытия фокус и ввод остаются на месте.
4. Защитить успешные ответы и ошибки одинаковой проверкой актуальности запроса.

Приёмка: при защитной очистке тестовые 30 точек ДАРС остаются; при явном удалении удаляются. Черновик переживает отмену закрытия и временную ошибку API.

## Этап 1. Правдивые результаты и понятные ошибки

Замечания Q04, Q06, Q09; интерфейсные ошибки Q10.

- Дневной цикл показывает «нет данных», «выполнен с предупреждениями» или «выполнен». Ошибки источников и непересчитанные скважины видны отдельно от ошибок ИИ.
- Долгое ожидание имеет конечный срок, job ID и возможность повторно проверить статус. Прекращение клиентского ожидания не объявляется остановкой серверной работы; повторная отправка изменяющих запросов не делается автоматически.
- Ошибки конкретного действия показываются рядом с ним, по-русски и с названием поля. Отличать отсутствие сети, 401/403, неподходящий формат, редирект и отказ расчёта.
- Баллы НТЦ показывать как сумму и порог критичности, без ложного «15 из 14». Исправление текста не меняет формулу/индекс.

Приёмка: пустая БД не даёт сообщения «рейтинг пересчитан»; источник с 401 даёт понятную причину; 302/HTML не называются повреждением Excel; тестовые численные результаты до/после совпадают.

## Этап 2. Подключение источников без обязательной ручной правки файлов

Замечания Q05–Q07.

### Предлагаемый пользовательский путь

1. `mai.cmd setup` предлагает необязательный шаг «Источники данных»: оставить загрузку файлами либо открыть настройку источников.
2. Отдельная команда `mai.cmd sources configure` показывает ДАРС, ХИМИК, ЭРА ремонта и расписание бригад. Пользователь выбирает источник, вводит URL и при необходимости Bearer-токен скрытым вводом; может оставить прежнее значение или явно удалить его. Остальные настройки сохраняются, перед записью создаётся резервная копия.
3. Для автоматической загрузки пустого фонда предлагается список ID скважин. Уже загруженный фонд можно использовать без повторного ввода.
4. `mai.cmd sources check --well <ID>` показывает этапы: URL → HTTP → ожидаемый формат → найденный лист/заголовки → число подходящих строк. Проверка читает и разбирает ответ без импорта в БД и изменения рейтинга.
5. В дашборде появляется блок/раздел «Источники»: режим, состояние и время последней загрузки, ошибки/количество записей, краткая инструкция настройки. Токены и содержимое .env в браузер не передаются.

### Границы

- Сохраняются существующие MAI_SOURCE_*_URL/TOKEN, source_profiles.json, push API и адаптеры. Не требуется перенастроить уже работающие подключения.
- В отчёте/check видны все четыре источника; «файлы» — нормальный режим, «адаптер отсутствует» — ошибка, а заданный URL сам по себе не означает проверенную связь.
- Для ДАРС/ХИМИК/ЭРА прямой HTTP-путь по-прежнему ожидает XLSX, для расписания — JSON. Произвольный корпоративный JSON, SSO/OAuth или прямые SQL-таблицы внешней системы не обещаются без согласованного контракта адаптера.
- Диагностика объясняет, что делать с несовпадающими колонками, листом и строкой шапки. До исправлений проверить один файл с заголовком ниже первой строки в ручном и HTTP-режимах; обеспечить согласованный результат при авторежиме, сохранив явные настройки профиля.
- SQL Server в setup явно обозначается как хранилище приложения, а не как витрина источника. После изменения настроек сообщается о необходимом перезапуске.

Приёмка: человек подключает готовый GET→XLSX источник и расписание без редактирования .env; получает понятные ошибки 401/403/404/302/HTML/тайм-аута и неверных колонок; секреты не появляются в отчёте. Реальные корпоративные точки подключаются только по предоставленным владельцем адресам и контрактам.

## Этап 3. Удобство первого запуска, рейтинга, документов и CO₂

Замечания Q08, Q10, Q11. Визуальные изменения уточняются на заполненном стенде после восстановления браузерного доступа; непроверенный вариант не объявляется готовым.

### Рейтинг и начало работы

- Вместо технической строки env-переменных на первом пустом экране: «Загрузить файлы» и «Как подключить источники», с коротким объяснением следующего шага. Указать, какие учебные примеры доступны и как подготовить актуальные демофайлы существующим генератором; автоматическую загрузку примеров в рабочую БД не добавлять.
- Два режима таблицы: **«Кратко»** для обзора и **«Полно»** с существующими 13 колонками. Состояние выбора сохраняется. В кратком виде видны скважина/месторождение, индекс, мероприятие, срок и полнота данных; подробные основания доступны в карточке.
- Отдельный доступный фильтр РИ наряду с ППР/УДР; явное «показано N из M», включая скрытые скважины без оценки.
- Основной текст не мельчить ради всех колонок. Проверить 1280×720, 1366×768, широкий и узкий экран, увеличение масштаба и клавиатуру.
- Настройки доступа, помощь и версия — в блоке диагностики; основная панель оставляет рабочие действия. Поле ключа остаётся доступным, когда требуется авторизация.

Ориентир краткого вида:

| Скважина / месторождение | Индекс | Мероприятие | Крайний срок | Данные |
|---|---|---|---|---|
| DEMO-001 / Северное | 100 | ППР | 26.11 | Полные |

### Документы

- История с понятным «показано N из M», постраничным доступом и поиском по файлу/скважине/статусу. Старые файлы остаются доступны после появления 201-го документа.
- Обработка, принятая версия и ошибка повторной попытки различимы. Развёрнутые детали не сбрасываются при опросе статусов.
- Проверить навигацию к документу из карточки, повторную загрузку, скачивание оригинала, предупреждения перед удалением и сохранение поискового фильтра.

### CO₂

- Явный выбор «Измеренная доля / Сценарии»; соответствующее одно значение или список с примером и единицами.
- Локальная проверка ввода и русские сообщения у полей; ошибки не теряют введённые значения.
- Один основной результат в карточке вместо двух одинаковых блоков, история остаётся доступной. После сохранения общего расчёта доступен переход к нужной скважине, включая скважину без индекса.
- Исходные значения показать с понятными названиями и единицами; технический JSON/хеш сохранить в раскрываемой диагностике.
- В предпросмотре импорта показывать предупреждения и что проверено/не проверено до подтверждения записи. Отсутствие ошибок формата не выдавать за полевую валидацию.

## Этап 4. Приёмка и поставка

1. Полный прежний набор 149 тестов и новые регрессии через pymssql и ODBC Driver 18. Ни skip/xfail, ни ослабление проверок не заменяют исправление.
2. Закрепить основные браузерные сценарии в автоматических тестах/CI: загрузка → рейтинг → карточка → решение → сохранение/отмена; CO₂ → предпросмотр/ошибки → запись → история; безопасная очистка; источник с отказом; устаревший ответ. Зависимости браузерных тестов остаются только в разработке/CI, вне standalone.
3. В CI проверять оба SQL-драйвера в явно подготовленном окружении. Реальный Windows smoke сохраняется.
4. Повторить пользовательский проход из ZIP, включая пустой запуск и ошибочную конфигурацию; зафиксировать скриншоты до/после и ограничения.
5. Локальный и GitHub-архивы одного итогового коммита, проверка манифеста, состава и SHA каждого. Сохранить предыдущую поставку для отката.

Все удаления/ошибки при QA воспроизводятся только на одноразовых синтетических данных. Рабочая БД и пользовательский docker-compose.override.yml не меняются. Перед рабочим обновлением остаются согласованный backup и проверка на копии.
