# Реестр мероприятий: Excel для инженера, JSON для агента

Инженер редактирует `outputs/response-rules-2026-11-16/response-rules.xlsx`.
Проверяемая копия для программы — `config/response_rules.json`, формат `schema_version: 2`.
Вместо прежнего сопоставления кодов рейтинга теперь используются показатели и пороги.
Версия 1 была черновой заготовкой; новый валидатор её не принимает.

## Что находится в Excel

**Мероприятия:** одна строка — одно мероприятие с пояснением, уникальным ID,
статусом, редакцией и полями согласования. Текст мероприятия и пояснение
редактируются непосредственно в ячейках.

**Условия:** произвольное число строк для каждого ID. Столбцы: связка,
показатель, оператор, числовой порог, единица, допустимая давность измерения в днях.
Группа «И» должна выполняться целиком. В группе «ИЛИ» достаточно одного условия.
Если есть обе группы, нужны все условия «И» и хотя бы одно «ИЛИ».
Сложные выражения вроде `(А И Б) ИЛИ (В И Г)` оформляют отдельными мероприятиями;
произвольный текст условий не разбирается языковой моделью.

**Справочник:** показатели, единицы, границы качества данных и инструкция.
Эти границы взяты из каталога показателей проекта. Это не пороги назначения мероприятий.
Формат процентов — число в процентах: 80 означает 80 %, а не 0,8.

## Начальные примеры для проверки инженером

| Условия | Мероприятие | Пояснение |
| --- | --- | --- |
| CO₂ > согласованного порога И обводнённость > согласованного порога | Увеличить частоту отбора проб | Уточнить состояние коррозионной среды. Частоту и состав анализов определяет инженер |
| Те же условия И измеренная скорость коррозии > согласованного порога | Внести предложение в график ППР о пересмотре дозирования ингибитора с рассмотрением увеличения дозы | Проверить эффективность защиты и согласовать изменение дозы по действующей методике |

Оба примера — черновики из обсуждения проекта. Пороги и допустимая давность
измерений оставлены пустыми для инженера. Измеренная скорость коррозии в примере
служит конкретным признаком для проверки, не исчерпывает другие признаки коррозии.
Результат NORSOK и значения по умолчанию не подменяют измерения этих условий.

## Добавление, изменение и удаление

1. Для нового мероприятия добавить строку на листе «Мероприятия», задать ID
   латиницей (строчные буквы, цифры, подчёркивания), редакцию 1, статус «Черновик».
2. На листе «Условия» добавить строки с тем же ID, выбрать показатели и операторы,
   указать единицы, пороги и давность. Доступны `=`, `>`, `>=`, `<`, `<=`, «Нет данных».
   Для «Нет данных» порог не заполняют. Нулевая величина не означает отсутствие данных.
3. Для удаления удалить мероприятие и все строки его условий. При импорте JSON
   строится заново из всего файла: удалённые записи не сохраняются из прошлой версии.
   Можно удалить все мероприятия; получится пустой реестр.
4. При содержательном изменении увеличить редакцию, вернуть запись на проверку,
   убрать прежние сведения согласования. Изменения фиксировать в Git или архиве версий.

Строки можно сортировать и добавлять ниже таблицы. Скрытые и отфильтрованные строки
также импортируются. Полностью пустые строки пропускаются; частично заполненные
строки не удаляются автоматически. Названия листов и заголовки строки 5 сохраняют.
Формулы и ячейки с ошибками в таблицах не допускаются.
Процентный формат ячейки порога также отклоняется: используйте обычное число
в указанной единице, чтобы 80 % не превратилось в порог 0,8 %.

## Согласование

Статусы: «Черновик», «На проверке», «Согласовано», «Архив».
Для «Согласовано» обязательны инженер, дата, методическое основание (документ,
редакция и пункт), все пороги и давность данных. Инженер проверяет применимость,
исключения, границы, примеры с недостаточными и противоречивыми данными.

Валидатор проверяет заполнение и структуру, а не техническую правильность методики
или подлинность отметки инженера. Проверку достоверности измерений и конфликтов
между мероприятиями потребуется реализовать при подключении к агенту.

## Перевод Excel в JSON

Из корня проекта в окружении с установленными зависимостями:

```sh
python scripts/import_response_rules.py outputs/response-rules-2026-11-16/response-rules.xlsx --output /tmp/response-rules-candidate.json --revision 1
python scripts/check_response_rules.py /tmp/response-rules-candidate.json
python -m pytest -q tests/test_response_rules.py
```

Конвертер проверяет названия полей, числовые типы и диапазоны, единицы, уникальность ID,
связи условий и заполненность согласования. Неизвестный показатель, условие без
мероприятия или неверный статус останавливают импорт. Текст «1,5» вместо числовой
ячейки не преобразуется молча: в Excel нужно ввести число согласно локали.

Для замены существующего JSON нужно явно передать `--replace`. Новая копия
сохраняется атомарно только после успешной проверки всего файла; при ошибке прежний
JSON сохраняется. `--revision` задаёт редакцию всего реестра. JSON — производная
копия Excel; редактировать два источника независимо не следует.

## Работающий режим агента

По умолчанию включён режим `demo`: активен `config/response_rules_demo.json`,
применяются только записи со статусом «Тестовое». Тестовые пороги: CO₂ > 1,5 %,
обводнённость > 80 %, для пересмотра дозирования дополнительно измеренная скорость
коррозии > 0,1 мм/год. Давность каждого измерения — не более 30 суток.
Это тестовые значения проекта, не нормативы и не инженерное согласование.
Excel с заполненными значениями: `outputs/response-rules-demo-2026-11-16/response-rules.xlsx`.

После изменения Excel обновите активный JSON:

```sh
python scripts/import_response_rules.py outputs/response-rules-demo-2026-11-16/response-rules.xlsx --output config/response_rules_demo.json --revision 2 --replace
```

При следующем формировании предложения файл читается заново, без перезапуска.
Ранее сохранённые предложения остаются историей; в карточке нажмите «Сформировать заново».
В предложении сохраняются редакции реестра и правил, SHA-256 содержимого,
время проверки, значения, пороги, даты, источники и результаты условий.

Для перехода на проверенные инженером правила администратор задаёт в `.env`:

```dotenv
MAI_RESPONSE_RULES_MODE=approved
MAI_RESPONSE_RULES_PATH=./config/response_rules.json
```

Изменение `.env` требует перезапуска. В этом режиме работают только записи
«Согласовано» с заполненными сведениями инженера; «Тестовое» никогда не применяется.
Для тестового режима можно явно задать `MAI_RESPONSE_RULES_MODE=demo` и путь к тестовому JSON.
Неверный или отсутствующий JSON блокирует новое предложение с HTTP 503;
произвольные рекомендации LLM вместо повреждённого реестра не используются.

Проверка условий выполняется сервером. Используются исходные значения с индивидуальной
датой и источником, без переносов и административных подстановок CO₂-модели.
Строки реестра НКТ без собственного времени наблюдения исключаются по источнику поля.
Будущие, устаревшие и недостоверные измерения не подтверждают обычное сравнение.
Противоречащие значения одного показателя в один момент требуют уточнения.
Оператор «Нет данных» означает отсутствие доступного измерения в заданный период;
конфликт или неверное значение не выдаётся за доказанное отсутствие измерения.
В режиме `approved` дополнительно исключаются измерения с явной меткой `synthetic`.

Все подходящие мероприятия добавляются в предложение; примеры тестового реестра
совместимы друг с другом. Автоматическое разрешение смысловых противоречий между
произвольными текстами мероприятий не реализовано: их совместимость проверяет инженер.
Если ни одно правило не подтверждено, новых действий и бригады нет, предлагается
инженерное рассмотрение. Код категории мероприятия сохраняется из рейтинга;
действия и пояснения берутся строго из реестра, без свободного дополнения моделью.

LLM необязательна. При её наличии сохраняется предложение бригады со сверкой расписания
и срока; действия, пояснения, основания и сводка в любом случае формируются сервером.
Ошибка LLM не мешает получить результат реестра; бригада тогда не назначается.
Прежний файл `response_examples.json` больше не определяет действия агента.

## Тестовые данные

В `examples/response_rules/` находятся три входных JSON для API:
`sampling.json` (одно мероприятие), `inhibitor.json` (два), `no_match.json` (нет совпадений).
Это отдельные скважины TEST-RULE-001…003, синтетические измерения от 16.11.2026.
Для более позднего прогона обновите дату на фактический момент теста.

На локальном QA-стенде без API-ключа пример загружается так:

```sh
curl --fail -H 'Content-Type: application/json' --data-binary @examples/response_rules/inhibitor.json http://127.0.0.1:18082/api/v1/ingestion/telemetry
curl --fail -X POST http://127.0.0.1:18082/api/v1/rating/wells/TEST-RULE-002/ai-proposal
```

В Windows-сборку включены тестовый Excel, JSON-реестры, примеры, конвертер и эта инструкция.
Для конвертации используйте поставляемый `runtime/python.exe scripts/import_response_rules.py …`.
