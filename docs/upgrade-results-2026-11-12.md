# Итоги утверждённого обновления corV2

Дата: 12.11.2026. Основание: утверждённые этапы 0–5 в [плане](upgrade-plan-2026-11-11.md); исходное [ревью](senior-review-2026-11-11.md) относится к `39cd71e`.

## Реализация

- **R01–R03, R08:** извлечение готовит вклад документа без записи; одна SQL-транзакция заменяет вклад и подтверждённые метаданные. Ошибка повторной обработки сохраняет прежние данные. Владение отделено от независимого импорта. Reset/delete запрещены для активной обработки; уникальный claim исключает запись просроченного обработчика. Пересчитывается объединение прежних и новых скважин. После отказа пересчёта принятые данные остаются, повторный расчёт выполняется дневным циклом.
- **R04–R07:** происхождение и срок актуальности определяются для каждого поля. Общий отбор настоящих наблюдений исключает переносы и срезы из трендов и семидневной устойчивости. Неизвестное обязательное отклонение закачки не подтверждает ингибирование; независимо подтверждённое защитное исполнение оборудования сохраняется как отдельная мера.
- **R09–R11:** сервер проверяет доступность и дату бригады, окно и срок мероприятия; корректное пустое расписание очищает прежнее. Упрощена дедупликация пропусков без потери дополнительных показателей. Публичный SourceCatalog заменяет приватную зависимость агента от сборщика рейтинга и повторную классификацию источников.
- **R12–R13:** PID связан с ожидаемым runtime и временем создания. Потерянный PID восстанавливается только по идентичности процесса и корню экземпляра. Неуспешная остановка блокирует restart. Ошибки компиляции и недостающие DLL останавливают сборку. Проверка CRC, SHA-256, состава и манифеста общая для локального и CI-пути.
- **R14–R15:** CO₂-контроллер вынесен в один JS-файл без frontend-сборки. Формы, раскрытие и запросы сохраняются по скважине; устаревший ответ не меняет другую карточку. Baseline проверяется на конечность, строгий порядок времени и невозрастание survival.
- CO₂-import выполняет parsing/SQL в worker thread; ID проверяются и результаты вставляются пачками. Тест на 20 оценках ограничивает число SQL-вызовов восемью вместо построчного пути.
- Ранги рассчитываются одним проходом после сортировки; равные оценки сохраняют места 1, 1, 3. Статистика скважин учитывает документные записи двумя пакетными запросами.

Функции API, документов, Excel, рейтинга, модели, CO₂, агента и Windows CLI сохранены. Преднамеренные изменения поведения: пустой список бригад возвращает 201 и очищает срез; reprocess/delete активного документа возвращают 409; без достаточных доказательств защитная скидка не применяется.

## Тесты до и после

До исправлений: исходные 94 теста зелёные; все 16 регрессионных проверок воспроизвели дефекты. Дополнительные контракты написаны перед соответствующими изменениями, включая SQL round trips, event loop, транзакционный rollback, смену скважины, claim и UI. Отдельный новый тест обнаружил нулевую статистику документной скважины до её исправления.

Полный финальный прогон через pymssql: **124 passed**, 1 предупреждение о тестовом HTTP-клиенте. ODBC-прогон и Windows CI фиксируются в итоговых доказательствах.

Финальные журналы и сведения об обеих поставках сохраняются вне Git в `standalone/dist/upgrade-2026-11-12/`. Полный запуск: `sh scripts/test_co2_local.sh`; второй драйвер: `MAI_TEST_SQL_DRIVER=pyodbc sh scripts/test_co2_local.sh`. Каждый использует временную SQL Server без открытых портов, отдельную сеть и удаляет собственные ресурсы.

Node: `node tests/dashboard.test.cjs` — сохранение черновиков/раскрытия, блокировка повторного submit и устаревший ответ после смены скважины. Нативный smoke на Linux проверил реальные start/status/restart/stop и восстановление PID. Windows workflow выполняет тот же smoke поставляемым portable Python.

Браузерная проверка работающего приложения на синтетическом стенде: 14 скважин; ввод 60 °C, 50 бар сохраняется после обновлений/повторного открытия; расчёт 0,5/1,5/3 % CO₂ даёт 1,84/3,83/6,10 мм/год и сохраняется в истории. Индекс скважины остаётся 100. Скриншот — в каталоге итоговых доказательств.

LLM/OCR и ответы агента проверены детерминированной имитацией. Живой внешний провайдер и производственная БД в проверках не использовались. Windows smoke проверяет реальные процессы и зависимости portable Python на локальном FastAPI probe; полноценный Windows-сеанс с рабочей SQL Server не имитируется этим smoke.

## Архитектура и объём

Удалены предварительное удаление/восстановление соседних документов, отдельные пути записи документа, приватный импорт каталога, построчный CO₂ SQL, повторный подсчёт рангов, произвольные Git-операции из сборочного скрипта и дублирующая проверка архива. Не введены универсальные repository/service/base-class слои. Чистые подготовка и расчёты отделены от транзакции применения и UI-состояния.

По diff приложения, дашборда, standalone, scripts и workflow: +729/−575 строк, итого **+154 строки** до добавления этой документации. Общий код не уменьшился: явное владение и совместимая миграция требуют нового кода. Снижение LOC не является основанием удалять проверяемую функциональность; измерения итогового diff сохраняются вместе с доказательствами поставки.

## Миграция и откат

1. Перед обновлением действующей системы остановить все старые API/worker-процессы и входящие загрузки; сделать согласованную SQL Server backup и копию `.env`/хранилища исходных документов. Проверить восстановление backup в отдельной БД. Эта задача не выполняет рабочее развёртывание.
2. Прогнать новую версию на восстановленной копии БД. `init_db()` добавляет `documents.claim_id`, таблицу `document_contributions` и индекс; переносит доказанно документные legacy batch `doc-<id>-%`, помечая storage_version=2. Перенос и метка атомарны; повторный запуск безопасен. Интеграционный тест реконструирует legacy-записи на временной SQL Server и проверяет повторный запуск/удаление. Реальная копия пользовательской БД не предоставлена и не проверялась.
3. Старые Excel-profile batch_ids могут одновременно принадлежать прямому импорту: вклад копируется, исходные внешние batch остаются; `legacy_external_batches_preserved=true` сообщает об этой неоднозначности. Удаление документа не удалит такие внешние строки. Автоматически восстановить историческое происхождение или уже потерянные данные невозможно.
4. Проверить число записей, источники, reprocess с ошибкой, удаление и рейтинг на копии; затем отдельно согласовать рабочее переключение. Старую и новую версии одновременно к одной БД не подключать.
5. **Откат требует согласованного восстановления БД и хранилища вместе со старым архивом.** Простая замена приложения старым ZIP недостаточна: старый код не читает document_contributions. Данные, загруженные после backup, предварительно сохранить и затем повторно загрузить из оригиналов. Старые архивы не удаляются.

Физические модели не переобучались. Полевая точность CO₂/A1/A2, остаточный ресурс и инженерная пригодность остаются за границами программной проверки.
