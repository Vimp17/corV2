# QA-аудит сборки с позиции нового пользователя

Дата: 12.11.2026. Архив: `mai-demo-win64-2026.11.12-61c902a.zip`, SHA-256 `c68e01857101d3802ba01d7ebb058237984cec8c9a903a8695e00853b259688d`.

## Что проверено и где границы

- Архив распакован с проверкой SHA/CRC. Приложение, интерфейс и конфигурация запускаются именно из ZIP в отдельной временной SQL Server 2022. На Linux используется Python 3.12 тестового образа; это не повторная интерактивная проверка установки на Windows. Windows smoke последнего выпуска ранее прошёл в CI.
- В браузере пройдены первый запуск без данных, запуск пустого дневного цикла и выбор/загрузка трёх учебных книг. API подтвердил результат этой UI-загрузки: 14 скважин, все 14 рассчитаны.
- На одноразовой БД воспроизведены ошибка повторной обработки и опасная очистка. После проверки учебные данные восстановлены.
- Источники проверены через локальный HTTP-сервер: 401, 302, JSON и HTML-страница входа. Реальные корпоративные источники и внешний LiteLLM не вызывались.
- Несохранённые правки, очистка и устаревшая ошибка воспроизведены выполнением фактических JS-функций поставки в Node с минимальной DOM-моделью. Это не заменяет последующую браузерную приёмку.
- Дальнейшее чтение браузера, а затем новый Docker-запуск остановлены технической ошибкой автоматической проверки разрешений HTTP 403. Мобильная вёрстка, клавиатурный проход и визуальная проверка заполненной таблицы в этом аудите пока не завершены. Ошибка доступа инструментов не считается дефектом приложения.

Доказательства и исполняемые пробы: `standalone/dist/qa-2026-11-12/`. Код приложения в этой фазе не менялся; новые тесты не выдаются за повторный полный прогон прежних 149 проверок.

## Подтверждённые дефекты

### Q01 · P1 · Очистка «с ошибкой» удаляет ранее принятые данные

Шаги: загрузить ДАРС как документ → вызвать неуспешный reprocess → убедиться, что предыдущий вклад сохранился → очистить failed/not_recognized.

Факт: файл перешёл `loaded → failed`, сохранив вклад по 14 скважинам. Затем очистка удалила этот вклад: у DEMO-001 точек ДАРС стало **0 вместо 30**. Интерфейс при этом пишет «Из них ничего не загружено — рейтинг не изменится» и отправляет DELETE без подтверждения. Статус последней попытки ошибочно принимается за отсутствие принятой версии.

Места: `dashboard/index.html` — openClearMenu/clearDocuments; `app/core/documents/pipeline.py` — delete_documents/_delete.

Исправление: серверная защита принятого вклада при обычной очистке ошибок; отдельное явное удаление данных; считать документы с сохранённым вкладом независимо от статуса последней попытки. Полное и одиночное удаление остаются доступными с честным подтверждением.

Доказательства: api-probe.json, clear-probe.json.

### Q02 · P2 · Закрытие карточки теряет несохранённое решение

openWell предупреждает при переходе к другой скважине, но closeWell безусловно сбрасывает cardDirty. Крестик, клик вне карточки и Esc вне поля вызывают этот путь. Повторный клик по той же строке также пересоздаёт форму без проверки.

VM-воспроизведение: drawerOpen=true/cardDirty=true → closeWell → подтверждений 0, drawerOpen=false, cardDirty=false.

Исправление: единая проверка несохранённых изменений для всех путей навигации; повторный клик по открытой скважине сохраняет форму. Проверить сохранение/отказ/ошибку сети и ожидание запроса.

Доказательство: unsaved-probe.json.

### Q03 · P2 · Поздняя ошибка другой скважины подменяет текущий блок ИИ

loadWellExtras проверяет selected/request для успешного ответа, но не в catch. Ответ B успешно показан, затем отказ прежнего A заменяет aiBox карточки B сообщением об A.

Исправление: одинаковая проверка актуальности для результата и ошибки; аналогично проверить остальные запросы деталей.

Доказательство: late-error-probe.json — selected=B, visible_ai_box содержит Error for old well A.

### Q04 · P2 · Дневной цикл сообщает об успехе без результата

В браузере на пустой БД получено: «Список скважин пуст. Укажите MAI_WELL_IDS или загрузите первые данные через API. Рейтинг пересчитан». runNow безусловно дописывает успех и выбирает предупреждение только по ошибкам ИИ, не по needs_configuration/source_failures. Долгий/зависший monitor job опрашивается без конечного срока ожидания.

Исправление: различать нет данных, частичный результат и полный результат; показывать ошибки источников, количество пересчитанных/ожидающих скважин. Ограничить ожидание и дать повторную проверку статуса, сохранив job ID. Клиентское прекращение ожидания не выдавать за остановку серверной задачи.

### Q05 · P2 · check не доказывает подключение и не показывает расписание

source_modes исключает json_schedule. Даже при заданном MAI_SOURCE_CREW_SCHEDULE_URL расписание отсутствует среди режимов — фактически возвращены только DARS, KHIMIK, ERA. cmd_check печатает через ok как «API», так и «адаптер не установлен», не делая запрос к источнику.

Исправление: все четыре источника, состояния «файлы», «настроен, не проверялся», «проверен», «ошибка»; отсутствующий требуемый адаптер не должен выглядеть успешной проверкой. Файловый режим сам по себе является нормальным состоянием.

### Q06 · P2 · Ошибки HTTP/авторизации маскируются под неисправный файл

Локальные пробы:

| Ответ источника | Текущее сообщение |
|---|---|
| 401 | Source request failed (HTTPError). |
| 302 + страница входа | Could not read this workbook; confirm it is a valid .xlsx file |
| 200 application/json | То же сообщение о книге |
| 200 text/html | То же сообщение о книге |

JSON для ДАРС/ХИМИК/ЭРА по URL сейчас не поддерживается — это ограничение контракта, а не ошибка вычислений. Проблема в диагностике: человеку не объясняется, что ответ отличается от ожидаемого XLSX. Редиректы не следует автоматически разрешать на произвольные адреса ради успешного статуса.

Исправление: русские причины HTTP/тайм-аута/TLS/неподходящего формата, ожидаемый тип ответа и конкретный следующий шаг. Не выводить токены или полный ответ системы авторизации.

## Подтверждённые неудобства и кандидаты на улучшение

### Q07 · P2 · Подключение источников вынесено в ручную правку .env/JSON

setup настраивает хранилище SQL Server, LiteLLM, даты и доступ, но не URL/токены источников или MAI_WELL_IDS. В README-DEMO раздел 6.5 предлагает открыть Блокнот, изменить .env, затем перезапустить. Изменение колонок требует source_profiles.json. При пустом фонде одного URL недостаточно: системе нужен список скважин.

В **локальном .env репозитория** URL/токены всех четырёх источников и MAI_WELL_IDS отсутствуют; внешний LLM также не задан. Значения секретов не выводились. Это не свидетельство о конфигурации другого, рабочего сервера.

Для готового GET → XLSX с Bearer настройка технически проста; текущий пользовательский путь сложен и плохо диагностируется. Для SSO, нестандартного JSON или прямого доступа к таблицам внешней системы понадобится согласованный адаптер. SQL Server в setup — хранилище приложения, а не автоматическое подключение к таблицам ДАРС/ХИМИК/ЭРА.

### Q08 · P2 · История документов ограничена без постраничного доступа

loadDocuments всегда запрашивает limit=200. Счётчик показывает все документы, но UI не предлагает следующую страницу или поиск по старым файлам. Это подтверждено кодом; сценарий с 201+ документами нужно закрепить регрессией до исправления.

### Q09 · P2 · Баллы НТЦ описаны как «из 14»

14 — порог критичности, а не максимально возможная сумма. Подписи rating_builder и renderRules могут показывать «15 баллов из 14». Нужно исправить текст на «15 баллов; порог критичности 14», сохранив расчёт.

### Q10 · P2 · CO₂ требует знания формата и перегружает карточку

Измеренный состав выбирается checkbox, но поле по умолчанию содержит три сценария. Ошибки API показываются без привязки к полю и часто на английском. Исходные значения отданы как JSON. В карточке результат одновременно находится внутри формы и в истории; это две визуальные копии одной оценки, а не доказательство дубликатов в БД. Предпросмотр импорта не показывает quality_flags принятых строк, хотя часть формул может быть непроверяема при отсутствующих входах.

Нужны явные режимы «Измерение / Сценарии», русские полевые ошибки, понятные исходные значения с единицами, предупреждения до подтверждения импорта и переход к карточке сохранённой скважины. Новые физические формулы и численные поправки сюда не входят.

### Q11 · P3 · Первый экран и плотность таблицы

На первом экране видны 13 колонок, повторяющиеся счётчики и техническая подсказка MAI_SOURCE_<ID>_URL. Ключ API занимает место в основной панели даже на локальном незащищённом стенде. Нет столь же заметного отдельного фильтра РИ, как у ППР/УДР. Кандидат: понятный первый шаг, краткий/полный вид таблицы, все меры в фильтре, настройки и версия в отдельном блоке. Полный утверждённый вид и Excel сохранить.

Это предложение по удобству, а не утверждение, что все экраны визуально проверены на каждом размере. Заполненный экран, 1280×720, 1366×768, узкий экран и клавиатурная навигация входят в обязательную последующую приёмку.

## Что работает

Первый экран явно сообщает об отсутствии данных; учебные ДАРС/ХИМИК/ЭРА загружаются одним выбором файлов и дают рейтинг 14 скважин. Повторная обработка действительно сохраняет прежний принятый вклад при отказе. В модели и интерфейсе CO₂ уже разделены мм/год, баллы и вероятность отказа. Код исходников совпадает с проверяемым ZIP. Проблемы очистки и текста об успехе не следует путать с ошибкой самой математической формулы.

## Дополнения при реализации одобренного плана

Доступ к браузеру и командам восстановился. Выполнены повторная загрузка трёх книг через интерфейс, визуальный проход краткого рейтинга при 1280×720 и 390×844, проверка HTTP 401 в карточке источника. Переполнения страницы по горизонтали в кратком режиме нет. Скриншоты: `07-rating-1280-after.jpg`, `08-mobile-after.png` в каталоге доказательств. Нативное подтверждение отдельно проверено автоматическим сценарием Chromium: отмена оставляет карточку и введённый комментарий, успешное сохранение переживает повторное открытие.

### Q12 · P1 · Импорт ответа одной скважины переприсваивает строки другой

Профиль HTTP/адаптера получает well_id запроса и использует его вместо ID каждой строки XLSX. Смешанный ответ QA-A + QA-B успешно проходил диагностику для QA-A. Это способно записать данные QA-B в QA-A. Новая регрессия сначала получила ошибочный `status=ok`; исправление отклоняет всю смешанную книгу до записи. Массовый ручной импорт сохраняется.

### Q13 · P2 · Неверный JSON расписания показывает сырой текст валидации

Локальный источник вернул лишнее поле date. В браузере показаны английская ошибка Pydantic, значение поля и техническая ссылка. Новая регрессия воспроизвела это до исправления. Диагностика теперь называет строку и поля JSON по-русски, не повторяя исходные значения; для периода поддерживаются available_from / available_to.

При доработке также закреплены регрессиями: ссылка общего расчёта CO₂ на ID отправленного запроса при изменении формы во время ожидания; тайм-аут API, охватывающий чтение тела ответа; отказ вместо ложного успеха при HTML/повреждённом JSON. Численные модели не менялись.
