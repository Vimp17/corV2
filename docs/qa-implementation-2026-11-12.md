## Поведение после исправлений

- Очистка ошибочных документов проверяет наличие принятого вклада в транзакции и сохраняет его. Явное удаление остаётся отдельным действием; подтверждение учитывает принятую версию независимо от статуса последней попытки.
- Карточка проверяет несохранённое решение при закрытии и переходах; повторный клик не пересоздаёт форму. Сохранение блокирует повторную отправку; отказ API сохраняет ввод. Устаревшие успехи и ошибки не заменяют детали другой скважины.
- Дневной цикл сообщает отсутствие данных и ошибки источников/расчёта, ограничивает ожидание и сохраняет job ID для повторной проверки. HTTP/JSON и полевые ошибки показаны у действия. Подписи НТЦ различают сумму и порог.
- `mai.cmd sources configure` настраивает четыре источника, сохраняет остальные параметры и создаёт .env.bak. `sources check --well ID` и `/api/v1/sources/{profile}/check` читают и проверяют ответ без записи данных и статусов. Обычный `check` различает настройку и проверенную связь. Смешанные ответы XLSX по одной скважине отклоняются до записи.
- Есть краткий/полный рейтинг, отдельный фильтр РИ, счётчик скрытых скважин, поиск и страницы документов. Развёрнутые детали сохраняются при опросе. Ключ и сведения о версии перенесены в настройки.
- CO₂ явно разделяет измеренную долю и сценарии, сохраняет черновики, проверяет ввод, показывает один основной результат и понятные исходные значения. Предпросмотр импорта показывает предупреждения до записи. После общего расчёта доступна карточка созданной скважины без индекса.
- В ZIP включён существующий генератор учебных книг; дополнительная установка Python не требуется. Руководство описывает первый запуск, реальные форматы источников и диагностику.

Архитектура сохранена: существующие парсеры, транзакции и обработчик документов; один модуль CLI источников, один API диагностики, отдельный небольшой JS-контроллер карточек источников. Новых сервисов, frontend-фреймворка и зависимостей в standalone нет. Playwright используется только разработкой и CI.
