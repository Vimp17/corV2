# Дополнительные исправления: следующий согласованный цикл

Основание — согласие пользователя на предложенные правки; этот выпуск выполняет рекомендованные пункты **1–4**. Постоянные браузерные проверки/матрица SQL-драйверов в CI и ограничение DOM-кеша остаются отдельными следующими пунктами 5–6; интерфейс в этом цикле не меняется.

## Изменения

1. **CO₂ v4.** Проверяются диапазон баллов 0–100, pH 0–14 как контракт данного импортного формата, флаг pH_estimated 0/1, положительные D_mm/P_atm, порядок и верхняя граница парциальных давлений. По правилам предоставленного `REPORT.md`: индивидуальный балл равен min(100; 200×скорость), итоговый — среднему трёх баллов. Базовая скорость сверяется по T_C и pCO2_mid. Допуск сравнений: rel_tol=abs_tol=1e-6. При отсутствии pCO2_mid или отдельных баллов сохраняется предупреждение о невозможности соответствующей проверки. A1/A2 не пересчитываются; чужие результаты не исправляются молча. Прежние сохранённые оценки не изменяются.
2. **Пересчёт.** Новая rating_recompute_queue хранит well_id, revision, queued_at, last_error. Заявки создаются в той же транзакции, что замена/удаление вклада документа, включая прежние и новые скважины. Успешный обработчик удаляет только свою revision: новая заявка не теряется при конкурентном обновлении. Отказ оставляет заявку и диагностическую ошибку, сдвигает её в конец очереди. Обработчики сериализуются существующим SQL application lock; отдельный брокер и новый сервис не вводятся.
3. **Миграция.** SQL выбирает только document_id/loaded/время старых версий, исключая текст и extraction. ISJSON и CASE защищают JSON-функции от SQL NULL/JSON null. Перенос старых вкладов создаёт заявки пересчёта атомарно. Неоднозначные внешние batch сохраняются по прежней консервативной политике.
4. **NuGet.** Прямая загрузка выполняется с тайм-аутом сокета 20 секунд и максимум тремя попытками; отказ доступа и ошибка сертификата не повторяются. Незавершённый файл удаляется. Registration/catalog метаданные фиксированной версии Python кешируются; каждый запуск всё равно сверяет пакет с официальным SHA-512 перед распаковкой. Нет отключения TLS и фиксированных IP в коде/обычной команде сборки.

## Восстановление пересчёта

Принятый документ сохраняет status=loaded даже при отказе служебной записи после commit. Пересчёт пытается выполниться сразу; необработанные заявки восстанавливаются при запуске приложения и затем на каждом цикле существующего document worker (при пустой очереди документов — примерно каждые 15 секунд). Один фоновый проход берёт до 200 заявок.

При MAI_DOCS_WORKER=false периодические повторы выполняются через существующий `POST /api/v1/documents/process-queue` (например n8n); начальная попытка восстановления при старте остаётся. Не требуется повторять OCR/LLM или заново загружать документ. Для скважины без исходных данных обработчик удаляет производные данные, не создаёт пустую новую оценку. Ошибка повторной попытки хранится в last_error; при исправлении причины следующая попытка завершает задачу.

Ранее существовавший recompute_wells возвращал failed, не бросая исключение; прежняя внешняя try/except не обеспечивала регистрацию такого отказа. Новый путь проверяет каждую скважину и сохраняет отказ независимо от памяти процесса.

## Обновление существующей системы

Сначала остановить старые процессы, сделать согласованную SQL Server backup и сохранить оригиналы документов/.env; проверить новую версию на восстановленной копии. init_db добавляет rating_recompute_queue; для создания нужны DDL-права, далее достаточно CRUD. Автоматическое обновление рабочей БД в эту задачу не входит. Правила предыдущей миграции/отката document_contributions продолжают действовать: откат на старую схему хранения требует восстановления согласованных БД и файлов, а не только замены ZIP.
