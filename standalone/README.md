# MAI Corrosion Control — демо-сборка для Windows Server без Docker

Отдельная сборка системы для **тестовой демонстрации на данных компании**. На сервере работает без Docker, без установки и без прав администратора: архив распаковывается в папку, настраивается одной командой и запускается.

**База данных.** По умолчанию используется **встроенный PostgreSQL**: он лежит в архиве, работает на том же компьютере от вашего имени и доступен только с него (`127.0.0.1`). Отдельный сервер БД для тестового показа не нужен. Позже `mai.cmd setup` переключит сборку на корпоративный PostgreSQL (раздел 5.5).

**Что работает — всё, как в основной версии:**
- рейтинг скважин и график ППР (ДДО);
- карточки скважин;
- загрузка ДАРС, ХИМИК, ЭРА ремонта и расписания бригад;
- документы: Excel, PDF, сканы, реестр коррозии НКТ;
- **предложение ИИ-агента** и **справка ИИ дневного цикла**, распознавание PDF и сканов — через ваш LiteLLM;
- дневной цикл кнопкой в дашборде или из n8n;
- выгрузка рейтинга в Excel.

**Что выключено в этой сборке:**
- **Запросы к источникам данных** (API ДАРС, ХИМИК, ЭРА, расписания бригад). Все данные загружаются вручную: дашборд («Загрузка данных», «Документы») или папка `inbox`.
- **Отправка предложений в Промайн.** Предложения сохраняются со статусом «не настроено».

Обе блокировки встроены в запуск и действуют, что бы ни было записано в настройках. Единственное исходящее соединение сборки — к вашему LiteLLM.

Дашборд в этой сборке тот же, что в основной версии.

## 1. Коротко: пять шагов

1. Администратор кладёт на сервер архив `mai-demo-win64-<версия>.zip` (и файл `.sha256` рядом). Он же открывает порт в брандмауэре и доступ к LiteLLM (раздел 4). Базу данных готовить не нужно — она встроенная.
2. Разблокируйте архив (свойства файла → «Разблокировать») и распакуйте в `C:\mai-demo`.
3. Откройте командную строку (`cmd`) и выполните:
   ```bat
   cd /d C:\mai-demo
   mai.cmd setup
   ```
   Мастер спросит, какую базу использовать (Enter — встроенную), адрес, ключ и модель LiteLLM, дату данных и доступ. Встроенная база создаётся и запускается тут же.
4. Проверьте и запустите:
   ```bat
   mai.cmd check
   mai.cmd start
   ```
5. Откройте ссылку, которую напечатает `start`, — вида `http://СЕРВЕР:8000/dashboard?key=…`. Загрузите данные (раздел 6) и показывайте.

После демонстрации: `mai.cmd cleanup` (раздел 11).

## 2. Что внутри архива

| Путь | Что это |

| `pgsql\` | Встроенный PostgreSQL 16.10 для Windows (официальная сборка EnterpriseDB: программы, библиотеки, служебные файлы; без pgAdmin) |
| `app\`, `dashboard\`, `config\`, `migrations\` | Приложение — тот же код, что в основной версии |

| `scripts\`, `docs\`, `examples\` | Служебные скрипты, описание API, примеры документов |

| `n8n-demo\` | Сценарии n8n с адресом этого сервера |

## 3. Требования к серверу

- **Windows Server 2016 / 2019 / 2022 / 2025, 64-бит.** Подойдёт и Windows 10/11 x64.
- **Место на диске:** около 1,2 ГБ на сборку, плюс данные и загруженные документы.
- **Память:** 2 ГБ свободной оперативной памяти (приложение и встроенная база).
- **Права:**
  - можно запускать программы из своей папки — `runtime\python.exe`, программы `pgsql\bin`, `mai.cmd`;
  - права администратора не нужны;
  - Visual C++ Redistributable не нужен: все библиотеки уже внутри.
- **Сеть:**
  - с сервера доступен LiteLLM;
  - со встроенной базой больше ничего не нужно; для корпоративного PostgreSQL — доступ к нему (раздел 5.5);
  - если смотреть дашборд с других компьютеров и из n8n — к серверу открыт входящий порт сборки (по умолчанию 8000).
- **Интернет не нужен.**
- **Путь к папке.** Короткий и латиницей, например `C:\mai-demo`. Длинные пути Windows и кириллица в пути могут мешать.

## 4. Что попросить у администраторов

Ниже готовый текст заявки. Отправьте нужные пункты как есть.

> **Заявка: тестовая демонстрация MAI Corrosion Control на сервере `<ИМЯ СЕРВЕРА>`**
>
> 1. **Перенос файлов.** Положить на сервер архив `mai-demo-win64-<версия>.zip` и файл `…zip.sha256`. Проверка целостности: `certutil -hashfile mai-demo-win64-<версия>.zip SHA256` — сумма должна совпасть с файлом `.sha256`.
>
> 2. **PostgreSQL — только при переходе на корпоративную базу** (для тестового показа не нужно: используется встроенная). PostgreSQL 12 или новее; расширения и права суперпользователя не нужны. Нужен пользователь, который может создавать таблицы в отдельной базе **или** в отдельной схеме общей базы. Примеры:
>    ```sql
>    -- Вариант А: отдельная база (предпочтительно)
>    CREATE ROLE mai_demo LOGIN PASSWORD '<пароль>';
>    CREATE DATABASE mai_demo OWNER mai_demo;
>
>    -- Вариант Б: отдельная схема в существующей базе <база>
>    CREATE ROLE mai_demo LOGIN PASSWORD '<пароль>';
>    GRANT CONNECT ON DATABASE <база> TO mai_demo;
>    CREATE SCHEMA mai_demo AUTHORIZATION mai_demo;
>    ```
>    Сообщить: адрес сервера БД, порт, имя базы, имя схемы (для варианта Б), пользователя, пароль, нужен ли SSL. Открыть доступ с `<ИМЯ СЕРВЕРА>` к порту БД (pg_hba.conf и сетевые правила).
>
> 3. **Брандмауэр Windows на `<ИМЯ СЕРВЕРА>`** — входящий TCP-порт **8000** (или другой выбранный) для профиля «Домен»: дашборд будут открывать по ссылке с рабочих мест, к нему же обращается n8n.
>    ```powershell
>    New-NetFirewallRule -DisplayName "MAI demo 8000" -Direction Inbound -Protocol TCP -LocalPort 8000 -Action Allow -Profile Domain
>    ```
>    Если Windows уже создала **запрещающие** правила для `C:\mai-demo\runtime\python.exe` (это бывает, когда при первом запуске в окне «Брандмауэр Защитника Windows заблокировал некоторые функции» нажали «Отмена»), их нужно удалить — запрет для программы сильнее разрешения для порта:
>    ```powershell
>    Get-NetFirewallApplicationFilter -Program "C:\mai-demo\runtime\python.exe" | Get-NetFirewallRule | Where-Object Action -eq Block | Remove-NetFirewallRule
>    ```
>
> 4. **LiteLLM.** Адрес (например `http://litellm.corp:4000`), ключ (virtual key) и имя модели. Для распознавания сканов и фото — имя модели, которая принимает изображения (может быть та же). Доступ с `<ИМЯ СЕРВЕРА>` к LiteLLM. Если LiteLLM доступен только через прокси — адрес прокси.
>
> 5. **n8n** (если показываем сценарии): доступ из контейнера n8n к `<ИМЯ СЕРВЕРА>:8000` (тот же порт, что в п. 3) и права импортировать сценарии и создать учётные данные (Credentials).
>
> 6. **Запуск программ.** Разрешить запуск `C:\mai-demo\runtime\python.exe` и программ `C:\mai-demo\pgsql\bin\` (если на сервере AppLocker или аналог). При необходимости — исключение антивируса для папки `C:\mai-demo` (обычно не нужно). Встроенная база слушает только `127.0.0.1`, правило брандмауэра для неё не нужно.

Для тестового показа со встроенной базой достаточно пунктов 1, 3, 4 (и 5, 6 при необходимости). Пункт 2 — когда переходите на корпоративный PostgreSQL. Выбор между вариантами А и Б значения не имеет: сборка работает с обоими. В варианте Б все таблицы приложения создаются только внутри выделенной схемы.

## 5. Установка

### 5.1. Распаковка

1. Найдите архив, который положил администратор. Если рядом есть файл `.sha256`, сверьте сумму:
   ```bat
   certutil -hashfile mai-demo-win64-<версия>.zip SHA256
   ```
2. **Разблокируйте архив:** правой кнопкой → «Свойства» → внизу отметьте «Разблокировать» → «ОК». Без этого Windows может предупреждать при каждом запуске. То же в PowerShell: `Unblock-File .\mai-demo-win64-<версия>.zip`.
3. Распакуйте архив в `C:\` (правой кнопкой → «Извлечь все…»). Получится папка `C:\mai-demo`. Можно выбрать другую папку, но путь должен быть коротким и латиницей.

> Если сервер общий, файл `.env` с паролями увидят все, у кого есть доступ к папке. Безопаснее распаковать в свой профиль (`C:\Users\<ваше имя>\mai-demo`) — если имя пользователя латиницей. Или попросите администратора ограничить доступ к `C:\mai-demo`.

### 5.2. Настройка: `mai.cmd setup`

Все команды выполняются в командной строке **из папки сборки**:
```bat
cd /d C:\mai-demo
mai.cmd setup
```
Мастер задаёт вопросы по очереди. Значение в [скобках] — по умолчанию: чтобы его оставить, нажмите Enter. При повторном запуске мастер подставляет уже сохранённые ответы, поэтому менять можно только нужное.

| Вопрос | Что ответить |
|---|---|
| **Где база** | `встроенная` (по умолчанию) — для тестового показа; `сервер` — корпоративный PostgreSQL (раздел 5.5) |
| **Порт встроенной базы** | 55432 (Enter). Другой — только если этот порт занят. Порт открыт лишь на этом компьютере |
| **Сервер БД, порт, база, схема, пользователь, пароль, SSL** | Только для `сервер`: из ответа администраторов (п. 2 заявки), подробно — раздел 5.5 |
| **Адрес LiteLLM** | Например `http://litellm.corp:4000` — сборка сама допишет `/v1/chat/completions`. Пусто — без ИИ |
| **Ключ LiteLLM** | Virtual key |
| **Модель** | Имя модели в LiteLLM для справки, предложения агента и разбора документов |
| **Модель для сканов и фото** | Имя модели, которая принимает изображения (по умолчанию — та же). `-` — сканы не распознаются, всё остальное работает |
| **Часовой пояс** | Часовой пояс дат в ваших файлах: `Europe/Moscow`, `Asia/Yekaterinburg` и т. п. |
| **Дата последних данных** | Если показываете **выгрузку за прошлый период** — дата самых свежих данных в файлах (ДД.ММ.ГГГГ). Пусто — данные текущие. Подробнее — раздел 6.3 |
| **Открывать по ссылке с других компьютеров и из n8n?** | `да` — дашборд доступен по сети (нужен п. 3 заявки); `нет` — только на самом сервере |
| **Порт** | 8000 или другой, если 8000 занят |
| **Имя или IP сервера для ссылки** | Имя, по которому сервер видят другие компьютеры, например `srv-demo.corp.local` |
| **Ключ доступа** | `новый` — создать; `оставить` — прежний; `нет` — без ключа (тогда данные видит любой, кто знает адрес) |

Результат записывается в `.env`, а прежняя версия — в `.env.bak`. Для встроенной базы мастер при первой настройке создаёт её (папка `pgdata`, 10–60 секунд), запускает и заводит базу данных приложения. Пароль встроенной базы генерируется сам и хранится в `.env`. В конце мастер печатает ссылку для демонстрации.

> Менять `.env` вручную можно (Блокнот), но удобнее заново запустить `mai.cmd setup`. После любого изменения — `mai.cmd restart`.

### 5.3. Проверка: `mai.cmd check`

Проверяет всё, что может сломаться, **до** демонстрации:
- библиотеки загружаются (на этом этапе видны проблемы с DLL и антивирусом);
- встроенная база: запускается, если не работает;
- подключение к базе, версия PostgreSQL, права. Если схемы ещё нет и прав хватает, она создаётся;
- создание или обновление таблиц приложения;
- LiteLLM: короткий запрос к модели и время ответа. Для модели сканов — тестовая картинка с текстом «MAI 4721», модель должна её прочитать;
- свободен ли порт;
- блокировки источников и Промайна, окна для архивных данных.

`[OK]` — в порядке, `[!]` — предупреждение, `[X]` — ошибка с подсказкой, что делать (раздел 13). Выполните `check` после установки и ещё раз в день демонстрации.

### 5.4. Запуск: `mai.cmd start`

Сначала запускается встроенная база, затем приложение — оба в фоне, окно командной строки можно закрыть. Через 5–30 секунд (первый запуск дольше) команда напечатает:
```
Встроенная база работает (127.0.0.1:55432).
Запущено за 6 с.
Работает (процесс 1234).
  [OK]  база данных подключена
  [OK]  языковая модель настроена
  [OK]  модель для сканов настроена

На этом сервере:  http://127.0.0.1:8000/dashboard
Ссылка для других: http://srv-demo.corp.local:8000/dashboard?key=…
```
- **На самом сервере** дашборд открывается по `http://localhost:8000/dashboard`. Ключ вводится один раз в поле «Ключ API» вверху страницы, но удобнее открыть ссылку с ключом.
- **С других компьютеров** откройте «Ссылку для других». При первом открытии браузер запоминает ключ (cookie на 30 дней) и убирает его из адресной строки. Дальше дашборд открывается по `http://сервер:8000/dashboard` без ключа.
- `mai.cmd link` — напечатать ссылку ещё раз.

`mai.cmd stop` останавливает и приложение, и встроенную базу.

> **Первый запуск и брандмауэр.** Windows может показать окно «Брандмауэр Защитника Windows заблокировал некоторые функции этого приложения» для `python.exe`. Если вы не администратор, **не нажимайте «Отмена»**: Windows запомнит запрет. Закройте окно крестиком и попросите администратора выполнить п. 3 заявки.

### 5.5. Переход на корпоративный PostgreSQL

1. Администраторы готовят базу или схему и пользователя (п. 2 заявки, раздел 4) и открывают доступ с этого компьютера к серверу БД.
2. Запустите `mai.cmd setup` и на первый вопрос ответьте `сервер`. Остальные ответы (LiteLLM, доступ) мастер подставит прежние — нажимайте Enter.

   | Вопрос | Что ответить |
   |---|---|
   | **Сервер (имя или IP), порт, база** | Из ответа администраторов |
   | **Схема** | Для варианта Б — имя схемы (например `mai_demo`); для варианта А — пусто |
   | **Пользователь, пароль** | Из ответа администраторов. Пароль при вводе не отображается |
   | **SSL** | `prefer` (по умолчанию); `require` — если администраторы требуют SSL |

   Мастер остановит встроенную базу, но её данные останутся в `pgdata`.
3. `mai.cmd check`, затем `mai.cmd restart`. Таблицы на сервере создаются сами.
4. **Данные встроенной базы на сервер автоматически не переносятся.** Обычно проще загрузить файлы заново. Если нужно перенести всё как есть и на сервере выделена отдельная база (вариант А), используйте программы из `pgsql\bin`. Пароль встроенной базы — строка `MAI_STANDALONE_PG_PASSWORD` в `.env`. Встроенная база при этом должна работать: `mai.cmd setup` → `встроенная` → `mai.cmd start`, после копирования — снова `сервер`.
   ```bat
   pgsql\bin\pg_dump.exe -h 127.0.0.1 -p 55432 -U mai -d mai_demo -Fc -f demo.dump
   pgsql\bin\pg_restore.exe -h <сервер> -p 5432 -U <пользователь> -d <база> --no-owner --no-privileges demo.dump
   ```
   Папку `data\documents` (оригиналы документов) не трогайте: записи в базе ссылаются на эти файлы.
5. Вернуться на встроенную базу: `mai.cmd setup` → `встроенная` → `mai.cmd restart`. Прежние данные встроенной базы на месте.

## 6. Демонстрация: данные и сценарий показа

### 6.1. Порядок загрузки

Данные загружаются в дашборде. Рейтинг пересчитывается после каждой загрузки.

1. **«Загрузка данных» → ДАРС** — суточные выгрузки: месторождение, статус, обводнённость, дебит, CO₂, хлориды…
2. **ХИМИК** — лабораторные пробы.
3. **ЭРА ремонта** — ремонты, демонтажи, акты разбора.
4. **Расписание бригад (JSON)** — если есть. Без него ИИ-агент не назначает бригаду и прямо об этом пишет.
5. **«Документы»** — акты, протоколы, паспорта (PDF, сканы, фото, Excel), **реестр коррозии НКТ** (Excel). Можно перетащить сразу несколько файлов или положить их в папку `C:\mai-demo\inbox`.

**До демонстрации проверьте по одному файлу каждого вида.** Если в выгрузке компании столбцы называются иначе, после загрузки будет видно, какие столбцы взяты в расчёт, а какие не распознаны. Недостающие названия добавляются в `config\source_profiles.json` (список синонимов в `field_map`). После этого — `mai.cmd restart` и повторная загрузка.

### 6.2. Сценарий показа (пример)

1. **Рейтинг скважин:** индекс, мероприятие и срок, категория фонда, среда, акты, защита, полнота данных; фильтры «Ожидают решения» и «Нет данных».
2. **Карточка скважины:** нажатие на строку → откуда взято каждое значение (источник и дата) → **«Сформировать предложение»** (ИИ-агент, раздел 7).
3. **«Выполнить дневной цикл»:** пересчёт по всем скважинам и справки ИИ для рискованных.
4. **График ППР (ДДО):** окна до крайних сроков.
5. **Документы:** загрузка скана или PDF → распознанные поля с цитатами → данные в карточке. Реестр НКТ — блок «Реестр коррозии НКТ» в карточке.
6. **Выгрузка рейтинга в Excel** — кнопка над таблицей.
7. **n8n** — сценарии ежедневного цикла и формы оператора (раздел 8).

### 6.3. Выгрузка за прошлый период

Система оценивает данные относительно **сегодняшнего дня**:
- телеметрия старше 48 часов — «устарела»;
- проба учитывается 30 дней;
- акт — 365 дней.

Если показывать выгрузку, например, за август, у всех скважин было бы «устарела», «нет пробы», «нет акта». Поэтому в `setup` укажите **дату последних данных**. При каждом запуске сборка расширит окна на число дней, прошедших с этой даты (`check` покажет итоговые окна). Свежесть телеметрии ограничена одним годом, поэтому выгрузку старше года система всё равно покажет как «устарела».

Чтобы убрать режим архива — `mai.cmd setup`, на вопрос о дате ответьте `-`, затем `mai.cmd restart`.

### 6.4. Чего ждать от расчёта

- **Модели и пороги.** Пороги и баллы правил унаследованы из демонстрационного pipeline: это индикаторы, а не подтверждённая вероятность отказа. Математическая модель (Кокса) в сборке не обучена, поэтому индекс считается по модели НТЦ (правилам) — в карточке это написано.
- **Минимум данных.** Для расчёта моделей по скважине нужно минимум 8 замеров за 28 дней, иначе — «Нет оценки». Такие скважины по умолчанию скрыты из «Все», показать их — переключатель «Показывать без оценки».

## 7. ИИ: что делает и где видно

| Функция | Где запускается | Где видно |
|---|---|---|
| **Предложение ИИ-агента** по скважине: мероприятие, срок, бригада, обоснование, чего не хватает | Карточка скважины → «Сформировать предложение» | В карточке; сохраняется у скважины. Если рейтинг потом изменился, карточка предупредит, что предложение устарело |
| **Справка ИИ дневного цикла** по рискованным скважинам | «Выполнить дневной цикл» в дашборде или сценарий n8n | Сохраняется у расчёта скважины. В интерфейсе дашборда её вкладка («Телеметрия и ИИ») скрыта, как в основной версии. Справку видно в результате выполнения сценария n8n и через API (`/api/v1/dashboard/risk-ranking`, поле `ai_report`) |
| **Распознавание документов**: PDF — тип и поля с цитатами, сканы и фото — OCR | Загрузка в «Документы» | В истории загрузок: строка документа → извлечённые поля |
| Excel-документы, реестр НКТ, протоколы в Excel | Загрузка | Разбираются **без ИИ** |

**Время.** Каждое предложение и каждая справка — один запрос к модели, то есть секунды или десятки секунд в зависимости от модели. Дневной цикл формирует справки по рискованным скважинам по очереди: при 10 скважинах это 10 запросов. Тайм-ауты — `MAI_LLM_TIMEOUT_SECONDS` (120 с) и `MAI_OCR_TIMEOUT_SECONDS` (180 с) в `.env`.

**Что уходит в модель:**
- рейтинг и показатели скважины, акты, пробы, строки реестра НКТ, документы скважины (названия и статусы), расписание бригад;
- для распознавания документов — текст документа, для сканов — изображения страниц.

Данные уходят **только** в указанный вами LiteLLM.

## 8. n8n

Дашборд умеет всё то же вручную. n8n нужен, чтобы показать автоматизацию: ежедневный цикл по расписанию и форму проверки скважины оператором.

1. Подготовьте сценарии с адресом этого сервера:
   ```bat
   mai.cmd n8n
   ```
   В папке `C:\mai-demo\n8n-demo` появятся два файла. Адрес берётся из `setup`. Если n8n видит сервер по другому имени или IP, укажите его явно: `mai.cmd n8n --api-url http://10.1.2.3:8000`. Названия получают приставку «[ДЕМО]», идентификаторы — новые, так что в общем n8n сценарии не пересекутся с чужими.
2. Перенесите файлы на свой компьютер (или откройте n8n прямо на сервере). В n8n: **Workflows → Import from File** — по одному файлу.
3. **Ключ доступа.** В n8n: **Credentials → New → Header Auth**:
   - Name: `X-API-Key`;
   - Value: ключ — та часть ссылки `mai.cmd link`, что после `key=`.

   Откройте каждый HTTP-узел сценария → Authentication: Generic Credential Type → Header Auth → выберите этот credential. Ключ в сам сценарий не вписывайте.
4. **Проверка связи.** Добавьте временный узел HTTP Request на `http://<сервер>:8000/health/live` и нажмите **Execute step**. Ответ `{"status":"alive"…}` — связь есть. Ошибка соединения — брандмауэр (п. 3 и п. 5 заявки) или неверный адрес.
5. **Показ:**
   - **«[ДЕМО] MAI | Ежедневный анализ риска и справка».** Нажмите **Execute workflow**. Сценарий запустит дневной цикл, через минуту заберёт итог и для каждой рискованной скважины запросит справку ИИ. Справки видно в выполнении последнего узла. Включать расписание (Active) для демонстрации не нужно.
   - **«[ДЕМО] MAI | Проверка скважины оператором».** Откройте форму (Test URL узла формы), введите номер скважины — n8n покажет результат.

Импорт администратором через командную строку тоже работает: `n8n import:workflow --input=<файл>`.

## 9. Работа на сервере: запуск, остановка, RDP, автозапуск

- `mai.cmd start` — запустить в фоне (встроенную базу и приложение); `mai.cmd stop` — остановить оба; `mai.cmd restart` — перезапустить (после изменения настроек).
- `mai.cmd status` — работает ли, есть ли связь с базой и моделью, ссылки.
- `mai.cmd run` — запустить приложение в текущем окне и видеть журнал. Ctrl+C или закрытие окна останавливают приложение; встроенная база продолжает работать — остановите её `mai.cmd stop`.
- `mai.cmd logs` — последние строки журнала; `mai.cmd logs -f` — следить за журналом (Ctrl+C — выйти).

**RDP.** Сборка работает, пока вы в системе на сервере. Уходя, **отключайтесь** (кнопка «Отключиться» или закрытие окна RDP), а **не** «Выйти» / «Выход из системы». При выходе из системы Windows завершает все ваши программы — и приложение, и встроенную базу. После перезагрузки сервера сборку нужно запустить заново: `mai.cmd start`.

**Автозапуск при входе** (если политика позволяет создавать задания; иначе — через администратора):
```bat
schtasks /Create /TN "MAI demo" /SC ONLOGON /TR "C:\mai-demo\mai.cmd start" /RL LIMITED
```
Удалить: `schtasks /Delete /TN "MAI demo" /F`.

**Остановка во время обработки документа.** `stop` завершает процесс сразу. Документ, который в этот момент распознавался, останется в статусе «Обрабатывается». После следующего запуска он сам вернётся в очередь — через 30 минут после начала обработки. Можно не ждать и нажать у него «Обработать снова».

## 10. Безопасность и данные

**Где лежат данные:**
- в базе PostgreSQL: во встроенной — в папке `pgdata` на этом компьютере; в корпоративной — в выделенной базе или схеме;
- оригиналы загруженных документов — в `data\documents`;
- журнал — в `logs`.

На другие серверы данные не копируются.

**Наружу уходят только запросы к LiteLLM** (раздел 7). Запросы к источникам данных и отправка в Промайн выключены в самой сборке — `mai.cmd check` это показывает.

**Ключ доступа:**
- Без ключа API отвечает отказом. Страница дашборда откроется, но данных не покажет.
- Ссылка с ключом даёт полный доступ к данным демонстрации, включая загрузку и удаление. Передавайте её только участникам.
- Чтобы отозвать все выданные ссылки: `mai.cmd setup` → «Ключ доступа: новый» → `mai.cmd restart`.

**Протокол.** Соединение идёт по HTTP, без шифрования, как в основной версии без обратного прокси. Для демонстрации внутри корпоративной сети это обычно приемлемо. Если требуется HTTPS — перед сборкой нужен обратный прокси, это делают администраторы.

**`.env`** содержит пароль к базе, ключ LiteLLM и ключ доступа. Не пересылайте его и ограничьте доступ к папке (раздел 5.1). Встроенная база принимает подключения только с этого компьютера (`127.0.0.1`) и только по паролю.

## 11. После демонстрации

1. Удалите данные демонстрации:
   ```bat
   mai.cmd cleanup
   ```
   Нужно подтвердить словом `УДАЛИТЬ`. Команда остановит сборку и удалит загруженные документы, содержимое `inbox` и журналы, а также:
   - со **встроенной** базой — её целиком (папку `pgdata`; при следующем запуске создастся пустая);
   - с **корпоративной** базой — **только таблицы этого приложения** в базе или схеме. С ключом `--drop-schema` удаляется ещё и выделенная схема, если она пуста.
2. Остановите сборку (`mai.cmd stop`) и удалите папку `C:\mai-demo` целиком (вместе с `.env` и `pgdata`). В реестре и системе сборка ничего не оставляет.
3. Попросите администраторов:
   - если использовалась корпоративная база — удалить базу или схему и пользователя PostgreSQL;
   - удалить правило брандмауэра;
   - удалить в n8n сценарии «[ДЕМО] …» и credential `X-API-Key`.
4. Если создавали автозапуск: `schtasks /Delete /TN "MAI demo" /F`.

## 12. Обновление сборки

1. Разработчик собирает новый архив (раздел 16), администратор кладёт его на сервер.
2. На сервере:
   ```bat
   cd /d C:\mai-demo
   mai.cmd stop
   ```
3. Распакуйте новый архив **в новую папку** (например `C:\mai-demo-new`). Перенесите в неё из старой папки:
   - `.env`;
   - `pgdata` — данные встроенной базы (сборка должна быть остановлена, шаг 2);
   - `data\documents`, чтобы сохранить загруженные документы;
   - при желании `inbox` и `logs`.
4. Переименуйте папки: старую — в `C:\mai-demo-old`, новую — в `C:\mai-demo`. Затем:
   ```bat
   cd /d C:\mai-demo
   mai.cmd check
   mai.cmd start
   ```
   Таблицы в базе обновятся автоматически. Если всё работает, удалите `C:\mai-demo-old`.

Версия сборки — `mai.cmd version`.

## 13. Неполадки

| Что видно | Причина | Что делать |
|---|---|---|
| `runtime\python.exe not found` | Архив распакован не целиком или команда запущена не из папки сборки | `cd /d C:\mai-demo`, распаковать архив заново целиком |
| «Это приложение заблокировано», SmartScreen, «Система администратора заблокировала» | Архив не разблокирован, или AppLocker | Разблокировать архив и распаковать заново (5.1); иначе — п. 6 заявки |
| `check`: `[X] numpy: … DLL load failed` | Антивирус удалил или заблокировал файл, или архив повреждён | Сверить SHA-256 архива, распаковать заново; исключение антивируса для папки. Visual C++ Redistributable сборке не нужен, но его установка администратором не повредит |
| `Встроенная база не запустилась` | Чаще всего занят порт, антивирус блокирует `postgres.exe` или папка сборки только для чтения | Текст ошибки и `logs\postgres.log`; другой порт — `mai.cmd setup`; исключение антивируса для папки (п. 6 заявки) |
| `Порт встроенной базы 55432 занят` | На компьютере уже работает другой PostgreSQL или программа на этом порту | `mai.cmd setup` → другой порт встроенной базы |
| `Пароль встроенной базы в .env не подходит к папке pgdata` | `.env` заменили или создали заново, а `pgdata` осталась от прежней настройки | Вернуть прежний `.env` (или `.env.bak`); если данные не нужны — `mai.cmd stop`, удалить `pgdata`, `mai.cmd start` |
| `Папка pgdata не пустая, но базы в ней нет` | Создание базы прервалось | Удалить папку `pgdata` и повторить `mai.cmd setup` или `mai.cmd start` |
| Папку сборки не удаётся удалить | Работает встроенная база (`postgres.exe`) | `mai.cmd stop`, затем удалить |
| `check`: нет подключения к БД — `timeout` / `could not connect` | Сеть или брандмауэр между сервером и БД, неверный адрес или порт | Проверить адрес и порт (`mai.cmd setup`); администраторам — сетевой доступ и `pg_hba.conf` |
| `password authentication failed` | Неверный пользователь или пароль | `mai.cmd setup`, ввести заново |
| `database "…" does not exist` | Неверное имя базы | `mai.cmd setup` |
| `no pg_hba.conf entry` / `SSL off` | Сервер БД не пускает с этого адреса или требует SSL | Администраторам — правило в `pg_hba.conf`; в `setup` — SSL `require` |
| `нет права создавать таблицы в схеме` | Пользователю не выданы права | Администратору БД: `GRANT USAGE, CREATE ON SCHEMA <схема> TO <пользователь>;` (или вариант А/Б из заявки) |
| `модель … не отвечает`: HTTP 401/403 | Неверный ключ LiteLLM | `mai.cmd setup` → ключ |
| HTTP 400/404 | Неверный адрес или имя модели | Адрес вида `http://litellm:4000` (сборка допишет путь), имя — как в LiteLLM |
| `ConnectTimeout` / `ConnectionError` к LiteLLM | Нет сети до LiteLLM или нужен прокси | Проверить доступ; для прокси — строки `HTTPS_PROXY=` и `NO_PROXY=` в `.env`, затем `mai.cmd restart` |
| `модель для сканов … не прочитала тестовую картинку` | Модель не понимает изображения | Указать vision-модель или `-` (сканы не распознаются) |
| `порт … занят` | Порт использует другая программа | `mai.cmd setup` → другой порт; администраторам — правило брандмауэра на новый порт |
| Ссылка не открывается с другого компьютера | Брандмауэр, неверное имя сервера или сборка слушает только сервер | Проверить на сервере `http://localhost:8000/dashboard`; п. 3 заявки; в `setup` — «Открывать по ссылке: да» и правильное имя |
| Дашборд открылся, но пишет про ключ | Открыт адрес без ключа в новом браузере или cookie истёк | Открыть ссылку с ключом (`mai.cmd link`) |
| Ссылка: «Ключ в ссылке не подходит» | Ключ сменили (`setup` → новый) | Взять новую ссылку: `mai.cmd link` |
| Документ: «OCR-модель не настроена» | Не указана модель для сканов | `mai.cmd setup` → модель для сканов; затем «Обработать снова» |
| Документ «Ошибка» после повторов | LiteLLM был недоступен или не ответил за отведённое время | Проверить `mai.cmd check`; «Обработать снова» |
| У всех скважин «Телеметрия устарела», «Нет пробы» | Показывается выгрузка за прошлый период | Указать дату последних данных (6.3) |
| Столбцы не распознаны | В выгрузке другие названия столбцов | Добавить названия в `config\source_profiles.json` (6.1), `mai.cmd restart` |
| `.env исправлен: кодировка ANSI…` | `.env` сохранён старым Блокнотом | Ничего: сборка исправила сама; для правок лучше `mai.cmd setup` |
| Сборка пропала после ухода с сервера | Вы вышли из системы, а не отключились, или сервер перезагрузили | `mai.cmd start`; уходя — «Отключиться» (раздел 9) |
| `API отвечает, но его процесс не найден` | Потерян `run\api.pid` | Диспетчер задач → `python.exe` из `C:\mai-demo\runtime` → снять задачу; затем `mai.cmd start` |
| n8n: `ECONNREFUSED` / timeout | n8n не видит сервер | Адрес в `mai.cmd n8n --api-url …`, брандмауэр (п. 3, 5) |
| n8n: 401 | Не выбран credential | Credential Header Auth `X-API-Key` во всех HTTP-узлах (раздел 8) |

Подробности любой ошибки — в `mai.cmd logs` (файл `logs\api.log`); встроенной базы — в `logs\postgres.log`.

### Как сообщить об ошибке

1. Сразу после ошибки выполните:
   ```bat
   mai.cmd diag
   ```
   Команда соберёт в один файл `diag\mai-diag-<дата-время>.txt`:
   - версию сборки и системы;
   - настройки (пароли и ключи заменены на `***`);
   - полный вывод `mai.cmd check`;
   - состояние приложения и встроенной базы, свободное место;
   - документы с ошибками — имена файлов скрыты;
   - последние строки журналов, где ключ из ссылок тоже скрыт.

   `mai.cmd diag --no-check` — быстрее, без проверки базы и модели.
2. **Просмотрите файл.** В журналах могут быть номера скважин — замените их, если нужно.
3. Отправьте файл разработчику и опишите: что делали, что ожидали, что получили, примерное время. Для ошибок загрузки — тип файла и строку заголовков столбцов (без данных).

Не отправляйте `.env`, ссылку с `key=` и сами данные.

## 15. Для ИТ: как устроена сборка

- **Процессы** — от имени пользователя, который их запустил:
  - приложение: `C:\mai-demo\runtime\python.exe -m uvicorn standalone.asgi:app --host <адрес> --port <порт>`;
  - встроенная база: процессы `postgres.exe` из `C:\mai-demo\pgsql\bin`, запуск и остановка через `pg_ctl` (данные — `pgdata`, только `127.0.0.1:55432`, вход по паролю, scram-sha-256).

  Служб, драйверов, записей в реестре и запланированных заданий сборка не создаёт (автозапуск — только если его создадите вы, раздел 9). Удаление — остановка и удаление папки.
- **PostgreSQL.** 16.10 x64 — официальные двоичные файлы EnterpriseDB (zip без установщика): только `bin`, `lib`, `share`; без pgAdmin, StackBuilder и процедурных языков Perl/Python/Tcl. Контрольная сумма архива EDB проверяется при сборке и записывается в `BUILD_INFO.json`. Visual C++ runtime (`vcruntime140`, `msvcp140` — файлы Microsoft) лежит рядом с программами базы.
- **Python.** 3.12.10 x64 из NuGet-пакета `python` (python.org, двоичные файлы подписаны Python Software Foundation). Контрольная сумма пакета сверяется с nuget.org при сборке и записывается в `BUILD_INFO.json`.
- **Библиотеки.** Устанавливаются при сборке из PyPI: готовые сборки под Windows x64, версии те же, что в проверенном Docker-образе основной версии (список — `standalone\requirements-windows.lock` и `BUILD_INFO.json`). При сборке проверяется, что каждой скомпилированной библиотеке хватает DLL. C/C++-рантайм лежит рядом с `python.exe` и в папках пакетов, системный Visual C++ Redistributable не нужен.
- **Сеть:**
  - входящий — один TCP-порт (по умолчанию 8000), HTTP;
  - исходящий — LiteLLM и (если выбран) корпоративный PostgreSQL; встроенная база — только внутри компьютера. Запросы к источникам данных и SMTP/API Промайна сборка не делает: при запуске их адреса принудительно очищаются (`standalone\asgi.py`).
- **Доступ.** Ключ `MAI_API_KEY`. Клиенты передают его в заголовке `X-API-Key`, браузер — через cookie `mai_api_key` (HttpOnly, SameSite=Lax, 30 дней), который ставит ссылка `/dashboard?key=…`.
- **База.** Таблицы создаются и обновляются миграциями Alembic при запуске (и в `mai.cmd check`). В варианте со схемой все объекты создаются в ней (параметр `options=-csearch_path=<схема>` в адресе подключения). Расширения PostgreSQL не используются.
- **Записывает на диск** только в папку сборки: `.env`, `pgdata`, `data\documents`, `inbox`, `logs`, `run`, `n8n-demo`, `diag`, кэш байт-кода `__pycache__`.

## 16. Для разработчика: как собрать архив

Сборка делается на Linux-машине с Docker из ветки `standalone-demo` (в ней основной код из `main` плюс папка `standalone/`):

```bash
git switch standalone-demo
git merge origin/main          # подтянуть последние изменения основной версии
standalone/build/build.sh      # → standalone/dist/mai-demo-win64-<дата>-<коммит>.zip и .sha256
```

- Сборка идёт в контейнере `python:3.12-slim` (другой образ — `MAI_BUILD_IMAGE=…`). Прокси машины передаётся в контейнер, на машине ничего не устанавливается. Скачанное (Python, пакеты, PostgreSQL) сохраняется в `standalone/dist/cache` и переиспользуется. Первая сборка скачивает около 470 МБ (из них 322 МБ — архив PostgreSQL от EDB, из которого берётся около 125 МБ).
- Версия PostgreSQL и SHA-256 её архива заданы в `standalone/build/build_windows.py` (`POSTGRES_VERSION`, `POSTGRES_SHA256`). При смене версии обновите оба значения. Мажорная версия должна оставаться прежней, иначе папку `pgdata` прежней сборки новая база не откроет.
- Версии пакетов зафиксированы в `standalone/requirements-windows.lock`. Если в `requirements.txt` основной версии изменились зависимости, подберите версии заново, согласовав их с проверенным Docker-образом:
  ```bash
  docker run --rm --entrypoint python corv2-mai-api -m pip freeze > standalone/dist/cache/tested-constraints.txt
  standalone/build/build.sh --relock --constraints /dist/cache/tested-constraints.txt
  ```
  Затем закоммитьте новый lock.
- Логику команд (`standalone/manage.py`, `standalone/asgi.py`) можно проверить и на Linux: `python standalone/manage.py <команда>` из корня репозитория, при установленных зависимостях `requirements.txt`.
- Ветка `standalone-demo` добавляет только папку `standalone/`. Файлы основной версии в ней не меняются, поэтому `git merge origin/main` проходит без конфликтов.
